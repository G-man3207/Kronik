The isolation level says how code is sandboxed: `wasm` for actors (the default), `gvisor` for foreign actors (their default, `runsc` with the systrap platform), `trusted` for what the operator chooses to trust (plain runc, with a warning), and `microvm` for Firecracker where KVM is available. `microvm` is an opt-in that gives each actor a VM of its own; its proofs passed on GitHub-hosted Ubuntu 24.04 runners, virtual machines on AMD hosts with nested KVM, on 2026-11-14. Its VMM runs as the daemon's own user under Kronik's own launcher, not under Firecracker's jailer with a user of its own, and every sandbox fork of a microVM actor resumes the same snapshot, so random state a program holds in memory repeats across forks (the operations guide has both). It needs a usable `/dev/kvm` and the pinned tool bundle in `[foreign] microvm_dir`; without KVM the add gives `KVM_UNAVAILABLE`, which suggests `gvisor`.
