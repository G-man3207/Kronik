The isolation level says how code is sandboxed: `wasm` for actors (the default), `gvisor` for foreign actors (their default, `runsc` with the systrap platform), `trusted` for what the operator chooses to trust (plain runc, with a warning), and `microvm` for Firecracker where KVM is available. `microvm` is experimental: its proofs have run only on hosted virtual machines with nested KVM (Ubuntu 24.04, 2026-11-14), and every add answers with a warning that says so. Its VMM runs as the daemon's own user under Kronik's own launcher, not under Firecracker's jailer with a user of its own, and every sandbox fork of a microVM actor resumes the same snapshot, so random state a program holds in memory repeats across forks (the operations guide has both). It needs a usable `/dev/kvm` and the pinned tool bundle in `[foreign] microvm_dir`; without KVM the add gives `KVM_UNAVAILABLE`, which suggests `gvisor`.

See also: `foreign-actor`, `KVM_UNAVAILABLE`.
