# M15 Python and Go SDKs

Status: binding for M15. Builds on `m1-core.md` (the actor world, the
deploy allowlist), ADR 0001 (the deterministic engine), ADR 0002 (how the
TypeScript SDK is built) and ADR 0030 (the Python and Go toolchains);
brief sections "v0.3: Rikare replay" → M15, "SDK:er och exempelappar" and
"Aktörs-ABI (WIT)".

Two more SDKs with exactly the API of the Rust and TypeScript ones, built
with componentize-py (Python) and TinyGo with wit-bindgen-go (Go), plus
example apps that pass the same acceptance scripts as the Rust and
TypeScript examples.

## 1. Layout

| Path | What |
| --- | --- |
| `sdk/python/` | The `kronik` package (`kronik/`), its WIT (`wit/kronik-actor.wit`), host-side unit tests (`tests/`). Pure Python; the bindings are generated by componentize-py at build time. |
| `sdk/go/` | The Go module `kronik.dev/sdk`: package `kronik` (the API), package `testkit`, the bindings generated by wit-bindgen-go v0.7.0 (`internal/wit/…`, committed, checked by CI like the TypeScript declarations), and the world `kronik:go/actor-go` (`wit/world.wit`: the actor world plus TinyGo's `wasi:cli/imports`, with TinyGo 0.43.0's WASI WIT in `wit/deps/`). |
| `examples/counter-py`, `notes-py`, `webhook-relay-py` | Python twins of the TypeScript examples (`--entry step2` builds `counter-py-step2.wasm`). |
| `examples/counter-go`, `notes-go`, `webhook-relay-go` | Go twins (`--entry ./step2` builds `counter-go-step2.wasm`). |
| `scripts/install-sdk-tools.sh` | The pinned toolchains (ADR 0030). |
| `scripts/build-examples-py.sh`, `build-examples-go.sh` | Build the examples into `examples/dist/` with `kronik build`. |

The brief names `counter` and `webhook-relay` for both languages; `notes`
is added in both because M1's acceptance (`scripts/acceptance-m1.sh`)
needs a SQL actor next to the counter, as `notes-ts` was for TypeScript.

## 2. The API

The same names as `@kronik/sdk` (TypeScript) and `kronik-sdk` (Rust), in
each language's spelling:

| Concept | TypeScript | Python | Go |
| --- | --- | --- | --- |
| actor type | `actor({kind, schemaVersion, routes, capabilities, http, message, timer, migrate})` | `actor(kind=…, schema_version=…, routes=…, capabilities=…, http=…, message=…, timer=…, migrate=…)` | `kronik.Actor{Kind, SchemaVersion, Routes, Capabilities, HTTP, Message, Timer, Migrate}` with `kronik.Export(a)` in `init` |
| state | `ctx.state.get/getText/getJson/set/setJson/setFor/delete/keys` | `ctx.state.get/get_text/get_json/set/set_json/set_for/delete/keys` | `ctx.State.Get/GetText/GetJSON/Set/SetJSON/SetFor/Delete/Keys` |
| SQL | `ctx.sql.query/execute` | `ctx.sql.query/execute` | `ctx.SQL.Query/Execute` |
| messages | `ctx.send`, `ctx.call(to, msg, compensate?)` | `ctx.send`, `ctx.call(to, msg, compensate=None)` | `ctx.Send`, `ctx.Call(to, msg, compensate)` |
| HTTP | `ctx.http.fetch` | `ctx.http.fetch` | `ctx.HTTP.Fetch` |
| crypto | `ctx.crypto.hmacSha256/signEd25519` | `ctx.crypto.hmac_sha256/sign_ed25519` | `ctx.Crypto.HMACSHA256/SignEd25519` |
| timers | `ctx.timers.schedule/cancel` | `ctx.timers.schedule/cancel` | `ctx.Timers.Schedule/Cancel` |
| time, randomness | `ctx.now()`, `ctx.random.bytes(n)` | `ctx.now()`, `ctx.random.bytes(n)` | `ctx.Now()`, `ctx.Random.Bytes(n)` |
| ids | `ctx.causalId()`, `ctx.self()` | `ctx.causal_id()`, `ctx.self()` | `ctx.CausalID()`, `ctx.Self()` |
| secrets | `ctx.secret(name)` (a handle), `ctx.secrets.reveal` | `ctx.secret(name)`, `ctx.secrets.reveal` | `ctx.Secret(name)`, `ctx.Secrets.Reveal` |
| privacy | `ctx.subject(s)`, `ctx.currentSubject()` | `ctx.subject(s)`, `ctx.current_subject()` | `ctx.Subject(s)`, `ctx.CurrentSubject()` |
| log | `ctx.log.trace…error`, `console.*` | `ctx.log.trace…error`, `print` (stdout, a log event) | `ctx.Log.Trace…Error` |
| outputs | `ctx.json/text/status/reply/none` | `ctx.json/text/status/reply/none` | `ctx.JSON/Text/Status/Reply/None` |
| errors | `throw new Rejected(…)`; anything else is `failed` | `raise Rejected(…)`; any other exception is `failed` | return `kronik.Rejected(…)`; any other error is `failed`; a panic is recovered into `failed` |

The API is synchronous for the guest (brief); the host blocks. Every SDK
error message that has a Kronik error code ends with `see: kronik explain
<CODE>`. Module scope (Python) and package initialization (Go) run when
the component is built (Python, pre-initialized) or in every fresh instance
(Go), never across turns: no state survives a turn (I3).

## 3. Build (`kronik build`, ADR 0030)

`kronik build` recognizes a project by its manifest: `Cargo.toml` (Rust),
`package.json` (TypeScript), `pyproject.toml` (Python), `go.mod` (Go).

- **Python.** `pyproject.toml`: `[project] name` is the component's name;
  `[tool.kronik] entry` (default `actor`) is the module in `src/` that
  defines `handler = actor(...)`; `[tool.kronik] sdk` (default
  `vendor/kronik-sdk`) is the SDK's directory. `kronik build` writes
  `.kronik/kronik_entry.py` (`Handler = export(handler)`) and runs
  `componentize-py -d <sdk>/wit/kronik-actor.wit -w actor componentize -p
  .kronik -p src -p <sdk> kronik_entry -o .kronik/<name>.raw.wasm`.
- **Go.** `go.mod`: the module path's last element is the name; the SDK is
  the directory of `replace kronik.dev/sdk => <dir>`; the entry (default
  `.`) is a package that calls `kronik.Export` in `init`. `kronik build`
  runs `tinygo build -target=wasip2 --wit-package <sdk>/wit --wit-world
  actor-go -o .kronik/<name>.raw.wasm <entry>`.
- **Both.** Then `wasi-virt <raw> --allow-clocks --allow-random
  --allow-stdio --allow-exit --allow-env -o <component>`, the allowlist
  check, and the input hash (project, SDK, tool versions, flags) in the
  `kronik-build-input` custom section; unchanged inputs keep the previous
  component. `--entry <module|package>` builds a variant
  `dist/<name>-<entry>.wasm`. Tools come from `$KRONIK_SDK_TOOLS/bin`
  (default `~/.cache/kronik/sdk-tools/bin`) and their versions must match
  ADR 0030's; a missing or different tool fails the build with the
  command that installs it.

`kronik init --lang python|go <name>` writes a counter project with the
SDK vendored and a test, as for TypeScript and Rust: Python in
`vendor/kronik-sdk`, Go in `kronik-sdk` with `replace kronik.dev/sdk =>
./kronik-sdk` (a `vendor/` directory would switch the go command to
vendored mode and fail without `vendor/modules.txt`);
`scripts/e2e-init.sh` covers all four languages.

## 4. Testkits

Both testkits drive `kronik test-host` (the in-memory node of the TypeScript
and Rust testkits) over its JSON-lines protocol: `TestHost.start()` /
`testkit.Start(t)` builds the project as `kronik build` does and deploys
it; `http`, `send`, `advance`, `stub`, `state` and the effect log behave as
in `@kronik/sdk/testkit`. Python tests run with `python3 -m unittest`, Go
tests with the host's `go test` in a separate package (the actor package
only compiles for TinyGo's wasip2 target).

## 5. Acceptance

| Criterion | How |
| --- | --- |
| The examples pass the M1 to M3 acceptance scripts | M1: `M1_GUESTS=py` and `M1_GUESTS=go` run `scripts/e2e-m1.sh` and `scripts/acceptance-m1.sh` with counter and notes. M2: `RELAY=examples/dist/webhook-relay-py.wasm` (and `-go`) run `scripts/e2e-webhook-relay.sh`; DST with `KRONIK_DST_RELAY` set to each (`--scenario webhook --seeds 0..200 --twice`). M3: `demo/verify-change.sh` with `COUNTER` and `COUNTER_NEW` set to the counter and its `-step2` build. |
| Imports within the allowlist | `check_imports` on every new component in CI's `sdks` step, and in `kronik build`. |
| Determinism | `KRONIK_DETERMINISM_COMPONENTS=<the six examples, absolute paths> cargo test -p kronik-sched --test sdk_determinism`: a sequence of inputs (migration, `configure`, every route with real ids, messages, the timers the turns scheduled) twice, each in a fresh world with the scheduler's SQL host and a stub effect gate; byte-identical outcomes, writes, messages, timers, SQL changes, fuel, logs and effect requests, and the sequence must commit turns, answer GETs by a created id and retry a failed fetch by timer. |
| Identity replay | `scripts/identity-examples.sh` covers the new examples (empty diffs in isolated and continuous replay). |

CI: `scripts/ci.sh sdks` installs the pinned tools, checks the Go bindings
are generated from the WIT, runs the SDKs' unit tests, builds the examples
with `kronik build`, checks their imports, runs the examples' tests, the
determinism test on them, and `scripts/e2e-init.sh` for Python and Go.
